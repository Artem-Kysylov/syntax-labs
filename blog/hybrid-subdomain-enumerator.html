Hybrid Subdomain Enumerator: Finding the Subdomains Your Main Domain's Hardening Never Reached

By Artem Kysylov

A hardened main domain tells you almost nothing about what's actually reachable. Attackers don't start at example.com — they start at the subdomains nobody remembers provisioning: a dev.example.com still running last year's unpatched build, a staging.example.com with debug mode left on, a jenkins.example.com or internal.example.com that was never meant to see the public internet at all. The main domain gets every security review, every header audit, every pentest. The forgotten subdomain gets none of that, and it's sitting on the exact same DNS zone.

That's the surface Hybrid Subdomain Enumerator (subdomain_enum.py) maps. It's a CLI tool that pairs two fundamentally different discovery methods — passive Certificate Transparency log mining and active DNS brute-forcing — because each one catches exactly what the other misses: CT logs surface historical and forgotten hosts no wordlist would ever guess, while brute-forcing confirms which hosts are actually alive right now, something a certificate log can't tell you on its own. Below is a breakdown of how the two get merged into one source-tagged result set, followed by the terminal output and the hardening steps that close what it finds.

Why Attack Surface Discovery Starts With Subdomains

Every subdomain is a separate deployment with its own code path, its own forgotten config, and often its own exemption from whatever hardening the main site went through. A staging environment exists specifically to test changes before they're safe — which means it's the one host in the zone most likely to be running debug mode, verbose error pages, or last month's unpatched dependency. An internal or admin subdomain was provisioned on the assumption that nobody outside the company would ever type its name — an assumption that DNS does nothing to enforce. None of this shows up by looking at the main site. It shows up only by finding the subdomain in the first place.

Relying on a single discovery method misses most of it either way. A pure brute-force scanner only finds what's in its wordlist — it will never guess payments-v2-deprecated.example.com unless that exact string happens to be in the dictionary. A pure passive scanner only finds what's been publicly logged — it has no way to tell you whether a host it found two years ago is still alive today, or whether a brand-new internal tool that never got a public certificate even exists. Combining both is what turns "some subdomains" into a result set close to the real attack surface.

"Certificate Transparency tells you what has ever existed. DNS brute-forcing tells you what's alive right now. Neither answers the other's question — which is exactly why a scanner that only does one of them is reading half the map."

Architecture & Code Breakdown

subdomain_enum.py is built around three cooperating pieces: a wildcard probe that runs before anything else to keep catch-all DNS records from poisoning every later result, a passive lookup against public Certificate Transparency logs, and an active DNS dictionary pass that gets merged with the passive results into one tagged list. Here's how each one works.

1. Wildcard DNS Detection

Before a single prefix gets brute-forced, the scanner checks whether the zone even has a meaningful "not found" state. A wildcard *.domain.com DNS record makes every possible subdomain resolve to the same IP — including ones that were never actually provisioned — which would otherwise turn a 30-entry wordlist scan into 30 false positives instead of real findings.

subdomain_enum.py Python 
def _detect_wildcard_ip(self, domain: str) -> str | None:
    """Probe a randomized subdomain that cannot legitimately exist.
    If it resolves anyway, the zone has a catch-all *.domain record —
    every brute-force guess will "hit" that same IP, turning a real
    scan into a flood of false positives unless we know to filter
    that IP out before anything is reported."""
    probe = f"nonexistent-wildcard-probe-948271.{domain}"

    try:
        return socket.gethostbyname(probe)
    except socket.gaierror:
        # No resolution for a guaranteed-fake name — this zone has no
        # wildcard record, so every later hit can be trusted at face value.
        return None

The randomized suffix (948271) matters as much as the probe itself — a static string like test.domain.com has a real chance of colliding with an actual provisioned host, which would wrongly disable wildcard filtering for the entire scan. A high-entropy, clearly nonsensical label is the only way to guarantee the probe can't accidentally be real.

2. Passive Certificate Transparency Recon

Every publicly trusted Certificate Authority is required to log every certificate it issues to a public, append-only Certificate Transparency log — that requirement exists to catch rogue CAs, but it has a convenient side effect for recon: every hostname that ever appeared on a certificate for a domain is discoverable, permanently, without the target ever seeing a DNS query. crt.sh exposes those logs as a queryable JSON API.

subdomain_enum.py Python 
CRTSH_URL = "https://crt.sh/?q=%.{domain}&output=json"


def _fetch_from_crtsh(self, domain: str) -> set[str]:
    """CT logs are public by design — every CA is required to publish
    every certificate it issues. Querying crt.sh surfaces years of
    historical subdomains (a decommissioned jenkins., an old staging-v1.)
    without sending a single DNS query to the target itself."""
    subdomains: set[str] = set()
    url = CRTSH_URL.format(domain=domain)

    try:
        resp = self.session.get(url, timeout=self.timeout)
        resp.raise_for_status()
        entries = resp.json()
    except (requests.RequestException, ValueError):
        # crt.sh rate-limits aggressively and occasionally returns malformed
        # JSON under load — a failed passive lookup should degrade the
        # scan, not crash it.
        return subdomains

    for entry in entries:
        # name_value can pack multiple SANs into one newline-delimited
        # field, e.g. "api.example.com\n*.api.example.com\nold-api.example.com"
        for raw_name in entry.get("name_value", "").split("\n"):
            name = raw_name.strip().lower().lstrip("*.")
            if name.endswith(domain):
                subdomains.add(name)

    return subdomains

The wildcard-stripping step matters more than it looks. A certificate issued for *.staging.example.com proves that staging.example.com exists as a real zone, but *.staging.example.com itself is a pattern, not a hostname — reporting it as a finding would be reporting a wildcard glob as if it were a live subdomain. Stripping the *. prefix is what turns a certificate pattern into an actual candidate worth resolving.

3. Active DNS Dictionary Lookup & Hybrid Merging

Passive results tell you what's been seen; they don't tell you what's alive. The brute-force pass resolves a curated list of 30 high-value infrastructure prefixes directly — the names most likely to point at something worth finding: api, staging, admin, gitlab, grafana, jira, internal, and two dozen others in the same spirit. enumerate is where this active set and the passive set from crt.sh come together.

subdomain_enum.py Python 
# 30 high-value infrastructure prefixes — the names most likely to
# front something worth finding, not a generic dictionary dump.
HIGH_VALUE_PREFIXES = [
    "api", "staging", "dev", "admin", "test", "vpn", "mail", "ftp",
    "jenkins", "gitlab", "grafana", "jira", "internal", "git", "ci",
    "sso", "auth", "portal", "dashboard", "beta", "demo", "uat",
    "monitoring", "kibana", "db", "backup", "old", "secure", "ns1", "mx",
]


def _bruteforce_dns(self, domain: str, wildcard_ip: str | None) -> dict[str, str]:
    """Resolve each high-value prefix directly — no external service
    involved, so this is the only part of the scan that touches the
    target's own DNS servers."""
    active: dict[str, str] = {}

    for prefix in HIGH_VALUE_PREFIXES:
        candidate = f"{prefix}.{domain}"
        try:
            ip = socket.gethostbyname(candidate)
        except socket.gaierror:
            continue

        if wildcard_ip and ip == wildcard_ip:
            # Every brute-force guess "resolves" on a wildcard zone — without
            # this check, a single catch-all record makes it look like all
            # 30 prefixes exist, when in reality none of them do.
            continue

        active[candidate] = ip

    return active


def enumerate(self, domain: str) -> list[Result]:
    wildcard_ip = self._detect_wildcard_ip(domain)
    passive_subdomains = self._fetch_from_crtsh(domain)
    active_map = self._bruteforce_dns(domain, wildcard_ip)

    # Union, not concatenation — crt.sh and brute-force frequently
    # rediscover the same host, and a de-duplicated set is what makes
    # source tagging below mean something instead of double-reporting.
    all_subdomains = passive_subdomains | set(active_map.keys())

    results = []
    for name in sorted(all_subdomains):
        in_passive = name in passive_subdomains
        in_active = name in active_map

        if in_passive and in_active:
            source = "crt.sh + DNS"
        elif in_active:
            source = "DNS brute-force"
        else:
            source = "crt.sh (passive)"

        # A name from crt.sh with no active resolution is still worth
        # reporting — it's a historical or dangling record, exactly the
        # kind of leftover a subdomain takeover targets.
        ip = active_map.get(name, "unresolved")
        results.append(Result(name, ip, source))

    return results

The three-way source tag is what makes the output actionable instead of just a list of names. "crt.sh + DNS" is a high-confidence, currently-live host. "DNS brute-force" is a live host that was never certificate-logged — often an internal tool fronted by a self-signed cert. "crt.sh (passive)" with an unresolved IP is the most interesting bucket of all: a name that used to point somewhere and doesn't anymore, which is precisely the shape of a dangling DNS record a subdomain takeover targets.

Seeing It Run

Pointed at a target domain, the scanner detects a clean (non-wildcard) zone, pulls back a handful of certificate-logged hosts going back several years, confirms which of the 30 brute-forced prefixes currently resolve, and prints a merged table with every row tagged by source and every IP marked live or unresolved.

Remediation: Closing the Gaps It Finds

Every finding here maps to attack surface that's either unnecessarily exposed or unnecessarily alive. A dangling CNAME — a subdomain still pointing at a decommissioned cloud resource, like a deleted S3 bucket or an expired app-hosting instance — is the single highest-value fix, because it's an open invitation to subdomain takeover: whoever claims the now-unowned resource on the other end inherits the subdomain, cookies and all.

zone-cleanup.txt DNS 
# Before: a stale CNAME pointing at a resource that no longer exists —
# this is exactly what subdomain_enum.py flags as "crt.sh (passive)"
# with an unresolved IP, or a live resolution to someone else's infra.
old-app.example.com.    CNAME    old-app-bucket.s3-website.amazonaws.com.

# After: the record is deleted outright, not just the underlying
# resource — a dangling CNAME with no destination is just as
# claimable as one pointing at a live-but-unowned endpoint.
# (remove the zone entry; nothing replaces it)

Two more habits close most of the rest. First, anything the scan tags as internal infrastructure — jenkins, gitlab, grafana, jira, internal, kibana, any admin or monitoring tool — has no reason to resolve on public DNS at all; put it behind a VPN or a Zero Trust proxy (Cloudflare Access, Tailscale, a WireGuard gateway) so the hostname might exist in a zone file but is unreachable without already being authenticated onto the network. Second, avoid wildcard DNS records unless a genuine multi-tenant architecture requires one — beyond defeating this exact kind of enumeration-based reconnaissance, a wildcard also means a single misconfigured catch-all can silently route traffic for a subdomain nobody intended to provision.
